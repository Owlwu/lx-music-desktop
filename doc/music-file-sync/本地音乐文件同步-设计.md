# 本地音乐文件同步 —— 设计与协议契约（PC ↔ Android）

> 本文是实现契约。PC（`lx-music-desktop`，Vue + Electron，同步服务端/客户端）与
> Android（`lx-music-mobile`，React Native，仅客户端）两端都按本文实现，协议字段名与语义必须一致。

## 0. 目标回顾

| 目标 | 落地方式 |
| --- | --- |
| 1. 可选择同步范围（精确到文件夹） | 新增设置「同步歌曲存放路径」作为根目录；在根目录下用**树状勾选**任意层级的文件夹作为同步范围（scope） |
| 2. 分辨新增/删除并可选择是否同步 | 每台设备保存「上次同步基线」。对比 本地当前 / 远端当前 / 基线 得到 4 类变更 + 1 类冲突，逐条勾选后再传输 |
| 3. 歌词文件一起同步 | 与音频同名同目录的 `.lrc` 视为该音频的伴生文件，随音频一起传输/删除，不单独出现在清单里 |
| 4. 两端路径不同 | 协议内一律使用**相对根目录**的 POSIX 风格相对路径（`/` 分隔）。绝对路径只存在于各端本地 |

## 1. 数据模型

相对路径 `relPath`：以根目录为基准、`/` 分隔、不含前导 `/`、不含 `.` / `..` 段。
绝对路径仅在各端本地由 `joinPath(root, relPath)` 得到，绝不进协议。

```ts
// 一个音频文件（.lrc 作为伴生信息挂在其上，不单独成项）
interface FileItem {
  path: string        // 相对路径，如 "Yunomi/xxx.flac"
  size: number        // 字节
  mtime: number       // 毫秒时间戳（仅用于展示，不用于两端相等性判断）
  lyric: LyricItem | null // 同目录同名的 .lrc
}
interface LyricItem {
  size: number
  mtime: number
}

interface FileIndex {
  folders: string[]   // scope 内出现过的所有文件夹相对路径（去重、排序），用于对端展示
  files: FileItem[]   // scope 内的音频文件（按 path 排序）
}

type FileGroupKey =
  | 'remoteAdded'     // 远端新增：远端有、本地没有、基线没有 → 可下载到本地
  | 'localAdded'      // 本地新增：本地有、远端没有、基线没有 → 可上传到远端
  | 'remoteDeleted'   // 远端已删除：基线有、远端没有、本地有 → 可删除本地文件
  | 'localDeleted'    // 本地已删除：基线有、本地没有、远端有 → 可删除远端文件
  | 'conflict'        // 两端都有但内容不同（size 不同）→ 二选一

interface PlanItem {
  group: FileGroupKey
  path: string
  localSize: number | null     // 本端没有则为 null
  remoteSize: number | null    // 对端没有则为 null
  localHasLyric: boolean
  remoteHasLyric: boolean
  defaultChecked: boolean
  defaultDirection: 'push' | 'pull' // push=以本地为准，pull=以远端为准
}

interface Plan {
  groups: Record<FileGroupKey, PlanItem[]>
  localRoot: string
  remoteRoot: string
}
```

### 1.1 内容相等性判断

`equalContent(a, b) = a.size === b.size`。
**只用 size，不用 mtime**：同一首歌在两台设备上的复制时间必然不同，用 mtime 会把所有文件误判为冲突。
size 相同即视为同一份内容。

### 1.2 变更分类（对每个 `relPath`，`inL`=本地有，`inR`=远端有，`inB`=基线有）

| inL | inR | inB | size 相等 | 分类 |
| --- | --- | --- | --- | --- |
| ✓ | ✓ | * | ✓ | 已同步，无动作 |
| ✓ | ✓ | * | ✗ | `conflict` |
| ✓ | ✗ | ✓ | – | `remoteDeleted` |
| ✓ | ✗ | ✗ | – | `localAdded` |
| ✗ | ✓ | ✓ | – | `localDeleted` |
| ✗ | ✓ | ✗ | – | `remoteAdded` |
| ✗ | ✗ | * | – | 无动作 |

`size` 比较只在 `inL && inR` 时有意义；`inB` 只在恰好一端存在时决定「新增」还是「已删除」。

### 1.3 基线更新

一次同步（含用户跳过未勾选项）结束后：
`newBaseline = { p | p ∈ 同步后本地索引 ∧ p ∈ 同步后远端索引 }`（按 path 求交集）。
即：只有两端都存在的文件才进入基线；被用户跳过的新增文件下次仍会被识别为「新增」并再次提示。

### 1.4 默认勾选

- `remoteAdded` / `localAdded`：默认勾选（`defaultChecked = true`）。
- `remoteDeleted` / `localDeleted`：**默认不勾选**（删除是破坏性操作，必须手动确认）。
- `conflict`：默认不勾选，`defaultDirection = 'pull'`（以远端为准）。

## 2. 传输协议

复用现有跨设备同步通道（加密 WebSocket + `message2call` RPC），新增一个 feature 模块
`musicFile`（`FeaturesList` 增加该名字，`featureVersion.musicFile = 1`）。

握手沿用现有模式：服务端 `featureVersion` 协商 → 服务端调用客户端 `musicFile_sync_finished()`
→ 客户端 `socket.moduleReadys.musicFile = true` → 服务端 `socket.moduleReadys.musicFile = true`。
握手阶段不做任何文件传输，同步由用户在任一端 UI 手动发起。

### 2.1 RPC 方法（两端都必须实现同一组，供对端调用）

| 方法 | 参数 | 返回 | 说明 |
| --- | --- | --- | --- |
| `musicFile_sync_finished` | – | `void` | 握手收尾（仅客户端需要实现；服务端由 `sync()` 内部设置标志） |
| `musicFile_get_root` | – | `string` | 对端根目录绝对路径（仅用于界面展示） |
| `musicFile_get_index` | `scope: string[]` | `FileIndex` | 按 scope 扫描并返回索引 |
| `musicFile_read_file` | `path: string, offset: number, size: number` | `{ data: string, eof: boolean }` | 读取一个分片，`data` 为 base64 |
| `musicFile_write_file` | `path: string, offset: number, data: string, isLast: boolean` | `void` | 写入分片，`offset === 0` 时截断重建 |
| `musicFile_delete_file` | `path: string, withLyric: boolean` | `void` | 删除文件，`withLyric` 为真时同时删除伴生 `.lrc` |

- 分片大小 `MUSIC_FILE_CHUNK_SIZE = 192 * 1024`（base64 后约 256KB）。
- 所有 `path` 参数必须通过与本地相同的 `assertSafeRelPath` 校验，非法直接抛错。
- 写文件必须自动创建父目录。
- 上传/下载都先写目标文件，完成后才继续下一个；同一时刻只允许一个同步会话。

### 2.2 本端驱动流程（在点击「开始同步」的那一端执行）

1. `localIndex = scanLocal(root, scope)`
2. `remoteRoot = await peer.musicFile_get_root()`；`remoteIndex = await peer.musicFile_get_index(scope)`
3. `baseline = loadBaseline()`（本端持久化）
4. `plan = buildPlan(localIndex, remoteIndex, baseline)`
5. 用户勾选后：
   - `remoteAdded` 勾选项 → 逐分片 `peer.musicFile_read_file` 后写本地（含伴生 `.lrc`）
   - `localAdded` 勾选项 → 读本地分片后 `peer.musicFile_write_file`（含伴生 `.lrc`）
   - `remoteDeleted` 勾选项 → 删除本地文件（含伴生 `.lrc`）
   - `localDeleted` 勾选项 → `peer.musicFile_delete_file(path, true)`
   - `conflict` 勾选项 → 按 `direction` 执行 push 或 pull
6. 重新扫描两端索引，`saveBaseline(intersection)`；进度通过事件回报 UI

### 2.3 安全校验

- `assertSafeRelPath(p)`：非空、不含 `\`、不以 `/` 开头、不匹配 `^[A-Za-z]:`、拆分后任一段为 `''`/`.`/`..` 即抛错。
- 只同步扩展名在 `AUDIO_EXTENSIONS = ['mp3','flac','ogg','oga','wav','m4a']` 内的文件（大写扩展名按小写处理）。
- 伴生歌词判定：`<去掉扩展名的 path>.lrc`，大小写按 `.lrc` 精确匹配（同时接受 `.LRC`）。

## 3. UI 契约

两端设置项：

| 设置键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `sync.musicFile.root` | `string` | `''` | 同步歌曲存放路径（本机绝对路径）；为空时功能不可用 |
| `sync.musicFile.scope` | `string[]` | `[]` | 已勾选的文件夹相对路径；为空表示「根目录全部」 |

两端界面元素（同一套语义）：

1. 根路径：显示当前路径 + 「选择文件夹」按钮。
2. 同步范围：以根目录为根的文件夹树，勾选任意层级；勾选某文件夹即包含其全部子文件夹。
3. 「扫描并比较」按钮：需要同步已连接，否则提示未连接。
4. 变更清单：按 5 个分组展示（远端新增 / 本地新增 / 远端已删除 / 本地已删除 / 内容不同），
   每条带勾选框；删除组默认不勾。冲突项带「使用本地 / 使用远端」方向选择。
5. 「开始同步」：显示当前文件与总体进度，可取消。
6. 同步完成提示与结果（成功/失败数量）。

## 4. 已知取舍

- 相等性只看 size：同名同大小但内容不同的文件不会被识别为冲突（音频文件极少出现）。
- 伴生 `.lrc` 不单独成项：单独新增/删除 `.lrc` 不会被识别，它始终跟随同名音频文件。
- 不做断点续传：中途取消会留下不完整文件，下次同步会因 size 不同而列为冲突。
- 基线只保存在「发起同步的那一端」；两端都发起时各自维护自己的基线。
